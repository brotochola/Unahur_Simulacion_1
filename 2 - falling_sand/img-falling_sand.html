Cómo funciona: Falling Sand

Material de cátedra — cada idea apunta al código.

01

Autómata celular

Grilla de celdas (aire / arena / piedra). En cada paso, cada celda decide mirando solo a sus vecinas. El comportamiento global emerge.

02

Reglas de un grano (procesarCelda)

  • Abajo vacío → cae.
  • Si no, diagonales; empate → al azar.
  • Piedra es sólida y nunca se mueve; la arena choca con ella.
03

Recorrido abajo → arriba

Evita que un grano se mueva varias celdas en el mismo paso.

04

Alternancia L↔R

Cancela el sesgo cuando dos granos compiten por el mismo hueco.

05

Imagen, mundo y piedra

La imagen va centrada arriba. convertir no inicia Play: quedás en pausa para dibujar piedra con el pincel. La arena se acomoda alrededor y la forma se deforma distinto.

06

Chunks 16×16 (CHUNK_SIZE)

Sin chunks: cada paso visita ancho × alto celdas. Con chunks solo se visitan regiones activas. Al mover un grano se despierta el chunk destino y vecinos si cruza un borde. Tras cada paso: chunkActivo = chunkDespertado. Si no hay movimiento y no quedan chunks activos → pausa automática.

07

SoA vs ImageData

SoA: arrays ocupado (0/1/2) + colorR/G/B; cada frame se copian a un ImageData para dibujar. Reutilizar el buffer (checkReusar) evita presión de GC por createImageData cada frame.

ImageData como mundo (checkImageData): la verdad es el buffer RGBA — α 0 = aire, 255 = arena, 200 = piedra. Los helpers (estaVacio, esArena, moverGrano, etc.) abstraen ambos backends.
