1. El Origen Histórico: ¿Cuándo y por qué apareció?

El algoritmo DDA (Digital Differential Analysis) nació en la década de 1960 en los albores de la computación gráfica y el diseño asistido por computadora (CAD). Originalmente, fue diseñado para interpolar líneas en pantallas de vectores y rasterizar segmentos de recta en grillas de píxeles con hardware extremadamente limitado.

El Problema de la Época

En los años 60 y 70, las computadoras no tenían unidades de punto flotante (FPU) dedicadas. Realizar multiplicaciones o divisiones con decimales dentro de un bucle de renderizado era increíblemente lento. El DDA solucionó esto al transformar ecuaciones diferenciales continuas de líneas en sumas iterativas simples (diferenciales discretas), usando únicamente adiciones dentro del ciclo principal.

En 1992, John Carmack (id Software) adaptó este principio de interpolación en grillas para el motor de Wolfenstein 3D. En lugar de dibujar una línea en la pantalla, el algoritmo se utilizó a la inversa: lanzar un rayo desde la posición del jugador a través de un mapa de celdas cuadradas para detectar colisiones con los muros en un espacio pseudotridimensional (2.5D).

2. El Método Naïve (Muestreo Fijo) vs. DDA

Para entender la genialidad del DDA, primero debemos analizar el método intuitivo o Naïve, que suele ser el primer intento de cualquier estudiante al codificar Raycasting.

El método Naïve consiste en avanzar el rayo en pasos constantes muy pequeños (pequeños diferenciales discontinuos) a lo largo de su vector de dirección:

// Estructura conceptual del método ineficiente (Naive)
while(distancia < maximo) {
    x_continuo += cos(angulo) * paso_fijo;
    y_continuo += sin(angulo) * paso_fijo;
    
    int celdaX = floor(x_continuo);
    int celdaY = floor(y_continuo);
    
    if (mapa[celdaX][celdaY] == PARED) dectectar_colision();
}
Problema del Método Naïve Solución con Algoritmo DDA
Efecto Túnel: Si el paso_fijo es muy grande, el rayo puede saltarse esquinas del mapa y atravesar paredes sin colisionar. Precisión Absoluta: El avance calcula de forma exacta la intersección geométrica de las líneas de la grilla. Es imposible saltarse una celda.
Muestreo Redundante: Si el paso es muy pequeño para ser seguro, el procesador evalúa la misma celda decenas de veces de forma innecesaria. Eficiencia Máxima: El algoritmo realiza exactamente un único ciclo por cada celda cruzada. No procesa la misma celda dos veces.
Aliasing de Texturas: Al golpear la pared con un paso fijo, la posición exacta del impacto en el eje del muro no es exacta, estirando las texturas. Mapeo de Textura Perfecto: Al conocer con precisión decimal dónde impactó la línea vertical u horizontal, el cálculo de textura es exacto.

3. Explicación de las Variables Matemáticas

El estado del algoritmo DDA se compone de tres grupos esenciales de variables que puedes ver reflejados en el panel de control interactivo de arriba:

  • La Posición Discreta (mapX, mapY): Representan los índices enteros de la celda de la grilla donde se encuentra la punta de prueba del rayo en la iteración actual.
  • Las Proporciones Fijas (deltaDistX, deltaDistY): Es la distancia total que el rayo debe avanzar sobre su propia trayectoria para recorrer una unidad completa en el eje X o en el eje Y. Se calculan usando las componentes del vector unitario:
    deltaDistX = abs(1 / dx) y deltaDistY = abs(1 / dy)
  • Los Acumuladores Dinámicos (sideDistX, sideDistY): Almacenan la distancia acumulada que el rayo ha recorrido desde su origen para alcanzar el próximo borde de celda (borde vertical para X, horizontal para Y).

4. El Bucle de Decisión paso a paso

En cada ciclo, el DDA no hace cálculos trigonométricos complejos. Solo realiza una comparación lógica extremadamente eficiente:

if (sideDistX < sideDistY) {
    sideDistX += deltaDistX; // Acumula distancia para la próxima línea vertical
    mapX += stepX;           // Avanza una celda en el eje X (izquierda o derecha)
} else {
    sideDistY += deltaDistY; // Acumula distancia para la próxima línea horizontal
    mapY += stepY;           // Avanza una celda en el eje Y (arriba o abajo)
}

Observa el panel de Traza del Bucle DDA mientras mueves el rayo arriba: el algoritmo evalúa cuál de las dos distancias acumuladas es menor, toma el camino más corto, salta a esa celda exacta y actualiza el acumulador de ese eje sumando su valor deltaDist correspondiente.
