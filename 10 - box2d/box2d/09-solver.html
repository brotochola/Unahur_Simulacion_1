El solver por dentro

Con los contactos y los joints ya calculados, falta lo central: encontrar los impulsos que hacen que nada se atraviese, que los joints se respeten y que la fricción frene. Ese es el solver. En esta página vemos cómo trabaja el de Box2D v3, por qué es estable, cómo se organiza para ir rápido y cómo evita que las cosas rápidas atraviesen paredes.

El soft step

Box2D v3 usa un solver que Erin Catto llama soft step: un solver de impulsos (como el del capítulo 1) con tres ideas encima:

  • Subpasos: en vez de un paso de 1/60 s con muchas iteraciones, hace 4 pasitos de 1/240 s con una iteración cada uno. Integrar más seguido corrige mejor que iterar más sobre posiciones viejas.
  • Restricciones blandas: cada contacto y cada joint se comporta como un resorte muy duro con amortiguación crítica, en vez de una corrección rígida (la de Baumgarte del capítulo 1). Eso evita que las correcciones metan energía y que las pilas "salten".
  • Relajación: al final de cada subpaso hace una pasada más sin el término de corrección, para sacar la velocidad artificial que dejó el resorte. Después aplica la restitución (los rebotes).
// lo que pasa adentro de b2World_Step(worldId, dt, subSteps), simplificado
fasesAmplia_y_Fina();                       // capítulo 5: contactos nuevos, manifolds
const h = dt / subSteps;
prepararRestricciones();                    // masas efectivas, anclas…
for (let i = 0; i < subSteps; i++) {
  integrarVelocidades(h);                   // gravedad, fuerzas, damping
  aplicarImpulsosAnteriores();              // warm starting
  resolver(h, { conCorreccion: true });     // contactos y joints blandos
  integrarPosiciones(h);
  resolver(h, { conCorreccion: false });    // relajación
}
aplicarRestitucion();
guardarImpulsos();                          // para el warm starting del próximo paso
colisionContinua();                         // ver abajo
actualizarIslasYDormir();

Warm starting

Una pila de cajas quieta necesita casi los mismos impulsos en cada paso. El warm starting arranca cada paso con los impulsos del paso anterior en vez de empezar de cero: así el solver ya está cerca de la respuesta y una sola iteración alcanza. Sin warm starting, una torre alta tiembla y se cae aunque nadie la toque.

Una torre de 20 cajas · b2World_EnableWarmStarting
¿Qué estoy viendo?
  • Veinte cajas apiladas. Con warm starting quedan firmes y se duermen.
  • Apagalo y reiniciá: con la misma cantidad de subpasos, la torre se hunde y se desarma.

Coloreo del grafo de restricciones

Resolver una restricción cambia la velocidad de sus dos cuerpos. Si dos restricciones comparten un cuerpo, no se pueden resolver al mismo tiempo: la segunda tiene que ver lo que hizo la primera. Pero dos contactos que no comparten ningún cuerpo dinámico sí se pueden resolver en paralelo, en hilos distintos o con instrucciones SIMD que procesan 4 u 8 a la vez.

Box2D arma un grafo: los cuerpos son nodos y cada contacto o joint es una arista. Después lo colorea: le asigna a cada arista un color de forma que dos aristas del mismo color nunca toquen el mismo cuerpo. Todas las restricciones de un color se resuelven juntas, y los colores van uno detrás de otro. Usa un coloreo goloso (a cada restricción le toca el primer color libre) con hasta 12 colores; los cuerpos estáticos no cuentan, porque nadie les cambia la velocidad.

El grafo de una pirámide · cada arista une dos cuerpos que se tocan
¿Qué estoy viendo?
  • Los puntos de contacto pintados por Box2D con el color que les asignó (drawGraphColors).
  • Con "Mostrar grafo" dibujamos nosotros el grafo: una línea entre los centros de cada par de cuerpos dinámicos en contacto, coloreada con el mismo algoritmo goloso. Los contactos con el piso no son aristas: el piso no se mueve.
  • Las barras de abajo cuentan cuántas restricciones hay de cada color: cada barra es un lote que se puede resolver en paralelo.
restricciones por color
// coloreo goloso: el que hace Box2D, sin las optimizaciones de bits
const cuerposDeColor = colores.map(() => new Set());
for (const c of contactos) {
  const a = c.cuerpoA.esDinamico ? c.cuerpoA : null, b = c.cuerpoB.esDinamico ? c.cuerpoB : null;
  let k = cuerposDeColor.findIndex(s => (!a || !s.has(a)) && (!b || !s.has(b)));
  if (k < 0) k = DESBORDE;            // si no hay color libre, va a una lista que se resuelve sola, en serie
  else { if (a) cuerposDeColor[k].add(a); if (b) cuerposDeColor[k].add(b); }
  c.color = k;
}

Phaser Box2D corre en un solo hilo de JavaScript, así que el coloreo no le da paralelismo; pero el algoritmo y el orden de resolución son los mismos que el de C, y por eso el resultado es igual.

Islas y sueño

Una isla es un grupo de cuerpos conectados entre sí por contactos o joints. Dos pilas que no se tocan son dos islas independientes: lo que pasa en una no afecta a la otra. Box2D mantiene las islas mientras simula (las une cuando dos grupos se tocan, y las parte cuando hace falta) y las usa para dormir: una isla entera se duerme cuando todos sus cuerpos están quietos, y se despierta entera cuando algo la toca.

Cuatro pilas, cuatro islas · cada color es una isla; gris es dormida
¿Qué estoy viendo?
  • Calculamos las islas a partir de los contactos (con un union-find) y pintamos cada una de un color. Cuando Box2D duerme una isla, todos sus cuerpos se ponen grises a la vez.
  • Arrastrá una caja de una pila: se despierta solo esa isla. Si la llevás hasta otra pila, las dos islas se unen en una.

Colisión continua y balas

Con pasos discretos, algo muy rápido puede estar antes de una pared en un paso y después en el siguiente, sin haberla tocado nunca: es el tunneling. Box2D lo evita con colisión continua (CCD): para los cuerpos rápidos calcula el tiempo de impacto (TOI) a lo largo del movimiento y los frena en ese instante. Por defecto lo hace entre dinámicos y estáticos (enableContinuous). Entre dos dinámicos es caro, así que solo lo hace si uno es bala (isBullet). Los contactos especulativos del capítulo 5 cubren casi todos los demás casos.

Un cañón contra paredes finas · arriba: pared estática · abajo: tablón dinámico
¿Qué estoy viendo?

  • Abajo, contra un tablón dinámico colgado: ahí la colisión continua normal no actúa. Solo si el proyectil es bala lo frena.
  • Los números cuentan cuántos pasaron del otro lado.

Para que ande rápido
  • Que duerma lo que está quieto (no lo despiertes con Set… innecesarios).
  • El escenario en cuerpos estáticos, y si es un contorno, en cadenas.
  • Pocas formas por cuerpo; círculos y cápsulas antes que polígonos cuando se pueda.
  • 4 subpasos alcanza casi siempre; subilos solo si una pila o un mecanismo lo pide.
  • Nada de dt variable ni de pasos de más de 1/30 s.
