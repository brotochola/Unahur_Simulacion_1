El cuerpo rígido

Antes de abrir Box2D conviene ver qué hay adentro. Un motor de física 2D de cuerpos rígidos es, en el fondo, un loop que integra las leyes de Newton para objetos que no se deforman y después corrige lo que la integración hizo mal: que se atraviesen, que se separen los que deberían estar unidos. En esta página armamos uno chiquito a mano.

Seis números por cuerpo

Un cuerpo rígido en 2D no se estira ni se dobla: todos sus puntos se mueven juntos. Por eso alcanza con muy poco para describirlo:

  • Posición (x, y) del centro de masa y ángulo θ.
  • Velocidad lineal (vx, vy) y velocidad angular ω (radianes por segundo).

Y dos números que no cambian: la masa m, que dice cuánto cuesta cambiarle la velocidad, y el momento de inercia I, que dice cuánto cuesta hacerlo girar. La inercia depende de cómo está repartida la masa: una barra larga cuesta mucho más de girar que un disco de la misma masa.

F = m·a    τ = r × F = rx·Fy − ry·Fx    α = τ / I   (fuerza → aceleración, torque → aceleración angular)

Si empujás un cuerpo justo en el centro de masa, solo avanza. Si lo empujás en otro punto, además gira: el torque es la fuerza por el brazo de palanca r, la distancia perpendicular entre el centro y la línea de la fuerza. Un impulso es una fuerza enorme que dura un instante (un golpe): cambia la velocidad de golpe, sin pasar por la aceleración.

¿Qué estoy viendo?

  • Al arrastrar ves la flecha del impulso J y el brazo r desde el centro hasta donde lo agarraste.
  • Abajo: cuánto cambia la velocidad (J/m) y la velocidad angular ((r × J)/I) con ese golpe.
  • Probá: golpeá la barra en la punta y en el centro con la misma fuerza. Después cambiá a disco y repetí.
class Cuerpo {
  constructor(m, I) { Object.assign(this, { m, I, x: 0, y: 0, a: 0, vx: 0, vy: 0, w: 0, fx: 0, fy: 0, t: 0 }); }
  fuerza(fx, fy, px, py) {                 // fuerza aplicada en el punto (px, py)
    this.fx += fx; this.fy += fy;
    this.t += (px - this.x) * fy - (py - this.y) * fx;    // torque = r × F
  }
  impulso(jx, jy, px, py) {                // cambio instantáneo de velocidad
    this.vx += jx / this.m; this.vy += jy / this.m;
    this.w += ((px - this.x) * jy - (py - this.y) * jx) / this.I;
  }
  paso(dt) {                               // Euler semi-implícito: primero velocidad, después posición
    this.vx += this.fx / this.m * dt; this.vy += this.fy / this.m * dt; this.w += this.t / this.I * dt;
    this.x += this.vx * dt; this.y += this.vy * dt; this.a += this.w * dt;
    this.fx = this.fy = this.t = 0;        // las fuerzas se acumulan durante un paso y se borran
  }
}

Box2D calcula masa, centro de masa e inercia solo, a partir de la forma y la densidad de cada pieza. Lo vemos en el capítulo de cuerpos.

Drag lineal y angular

En el espacio, un cuerpo empujado sigue para siempre. En un juego casi siempre queremos que frene: el aire, el agua, el roce con un piso visto desde arriba. La forma más barata es el drag (en Box2D, linearDamping y angularDamping): en cada paso se le saca a la velocidad una fracción proporcional a ella misma. El resultado es un frenado exponencial: rápido al principio y cada vez más suave.

v ← v · 1 / (1 + dt · c)    ω ← ω · 1 / (1 + dt · cang)   (lo que hace Box2D en cada paso)

En juegos El drag es la perilla de "sensación" más usada. Una nave de Asteroids con drag 0 es fiel a la física y difícil de manejar; con un poco de drag se siente controlable. En un top-down (autos, Hotline Miami) el drag lineal alto hace las veces de roce con el piso, y el angular evita que los objetos giren como trompos después de un choque.

Integrar: de fuerzas a posiciones

Newton nos da aceleraciones. Para mover cosas hay que integrar dos veces: de la aceleración a la velocidad y de la velocidad a la posición, de a pasos chicos dt. Cada forma de hacerlo es un integrador, y no todos son iguales: algunos inventan energía de la nada.

  • Euler explícito: avanza la posición con la velocidad vieja. Es el más obvio y el peor: en una órbita o un resorte gana energía en cada paso y explota.
  • Euler semi-implícito (o simpléctico): primero actualiza la velocidad y avanza la posición con la velocidad nueva. Cambiar el orden de dos líneas lo hace estable. Es el que usa Box2D.
  • Verlet: no guarda la velocidad, la deduce de la posición anterior: x' = 2x − xant + a·dt². Es estable y es la base de la dinámica basada en posiciones.
  • RK4 (Runge-Kutta de orden 4): evalúa la aceleración cuatro veces por paso y promedia. Muy preciso con dt grande, pero cuatro veces más caro y difícil de combinar con colisiones. En juegos casi no se usa.
// Euler explícito                      // Euler semi-implícito
x += v * dt;                            v += a(x) * dt;
v += a(x) * dt;                         x += v * dt;

// Verlet (posición actual y anterior)  // RK4: cuatro evaluaciones de la derivada por paso
const nx = 2 * x - xAnt + a(x) * dt * dt;
xAnt = x; x = nx;

¿Qué estoy viendo?
  • Arriba: el sol en el centro y la órbita que calcula cada integrador: Euler explícito, semi-implícito, Verlet y RK4.
  • Abajo: la energía total de cada uno respecto de la inicial. Una órbita real conserva la energía: la línea debería quedar plana en 0%.

error de energía (%)

El semi-implícito no conserva la energía exacta, pero el error oscila alrededor del valor correcto en vez de crecer. Esa propiedad (ser simpléctico) es lo que importa en un juego: preferimos una órbita un poco deformada a una que explota.

Restricciones: por impulsos o por posiciones

Integrar no alcanza: después de un paso, dos cajas pueden quedar encimadas, o los eslabones de una cadena pueden haberse separado. Esas reglas ("no atravesarse", "estar a 1 metro") se llaman restricciones (constraints). Hay dos grandes familias para cumplirlas:

  • Dinámica por impulsos (impulse-based): corrige velocidades. Para cada restricción calcula el impulso que anula la velocidad que la rompería, más un pequeño empujón proporcional al error (la corrección de Baumgarte). Es lo que hace Box2D.
  • Dinámica basada en posiciones (PBD): integra con Verlet y después mueve directamente las posiciones hasta cumplir cada restricción. La velocidad sale sola de la diferencia de posiciones. Es lo que popularizó Thomas Jakobsen con la tela y los ragdolls de Hitman (2000), y hoy se usa mucho para tela, sogas y pelo.

En las dos, las restricciones se resuelven de a una, y arreglar una desarregla un poco a las vecinas. Por eso se repite varias veces por paso: son las iteraciones. Con pocas, una cadena larga con un peso se estira como un elástico.

// impulsos: para cada eslabón (a, b) de largo L, muchas veces por paso
const n = normalizar(b.p - a.p), C = largo(b.p - a.p) - L;     // C: error de la restricción
const vRel = dot(b.v - a.v, n);                                // velocidad que estira o comprime
const lambda = -(vRel + beta / dt * C) / (a.w + b.w);          // w = 1/masa; beta: Baumgarte
a.v -= n * lambda * a.w;  b.v += n * lambda * b.w;

// posiciones: después de mover todo con Verlet
const d = b.p - a.p, C = largo(d) - L;
a.p += normalizar(d) * C * a.w / (a.w + b.w);
b.p -= normalizar(d) * C * b.w / (a.w + b.w);
En juegos Box2D, Havok y PhysX resuelven cuerpos rígidos con impulsos. Las sogas de Cut the Rope, la tela de una capa o el pelo de un personaje suelen ser partículas con Verlet y restricciones de distancia: baratas, estables y fáciles de "cortar". XPBD (2016) es la versión moderna de PBD que hace que la rigidez no dependa de cuántas iteraciones uses.

¿Y Box2D?

Todo lo de esta página está adentro de Box2D, en versión industrial: cuerpos con masa e inercia calculadas de las formas, integración semi-implícita, drag lineal y angular, y un solver de impulsos para contactos y joints. Lo que agrega es justamente lo difícil: detectar colisiones rápido entre miles de formas, generar los puntos de contacto correctos, la fricción, y un solver (el soft step) que se mantiene estable con pilas altas y masas muy distintas. Desde el próximo capítulo lo usamos de verdad.
