Audio en JavaScript

El navegador ofrece tres niveles para trabajar con sonido. Cuanto más bajo el nivel, más control (y más código). Un juego normalmente usa los tres: Audio para la música, la Web Audio API para los efectos y, si hace falta procesamiento propio, un AudioWorklet.

La clase Audio

El elemento <audio> de HTML, controlado desde JS.

+ Una línea de código, hace streaming.

− Latencia variable, una reproducción por elemento, casi nada de procesamiento.

Web Audio API

Un AudioContext con un grafo de nodos que se conectan entre sí.

+ Baja latencia, timing preciso, filtros, efectos, 3D, síntesis.

− Más conceptos: nodos, buffers, parámetros.

AudioWorklet

Tu propio código procesando muestra por muestra, en el hilo de audio.

+ Cualquier algoritmo; no lo frena el hilo principal.

− Hay que escribir DSP y cuidar el rendimiento.

1. La clase Audio

const musica = new Audio('musica.mp3');
musica.loop = true;
musica.volume = 0.5;
musica.play();            // devuelve una Promise

// para efectos que se superponen hay que clonar
const disparo = new Audio('disparo.wav');
function disparar() {
  const copia = disparo.cloneNode();
  copia.play();
}

Propiedades útiles: currentTime, duration, paused, playbackRate, preservesPitch, volume, muted. Eventos: ended, canplaythrough, timeupdate.

Probá disparar rápido (10 disparos cada 70 ms)

Con un solo elemento, cada disparo corta al anterior (o se pierde si todavía no terminó de rebobinar). Clonando se superponen, pero la latencia no es pareja. Con Web Audio cada disparo arranca exactamente cuando lo pedimos.

2. Web Audio API: AudioContext y el grafo de nodos

Todo pasa dentro de un AudioContext. Adentro armás un grafo: nodos fuente (generan sonido), nodos de procesamiento (lo modifican) y un destino (los parlantes). Los conectás con .connect(), como cables en una pedalera.

Política de autoplay: los navegadores no dejan sonar nada hasta que el usuario hace click o toca una tecla. El contexto arranca en estado "suspended" y hay que llamar a ctx.resume() dentro de un evento del usuario. Por eso los juegos web tienen la pantalla "click para empezar".

El reloj del audio es ctx.currentTime, en segundos, y avanza con precisión de muestra. Es independiente de requestAnimationFrame y de los FPS del juego.

Cargar y reproducir sonidos

const ctx = new AudioContext();

async function cargar(url) {
  const resp = await fetch(url);
  const datos = await resp.arrayBuffer();
  return ctx.decodeAudioData(datos);   // → AudioBuffer (float32)
}

const sonidos = {
  salto: await cargar('salto.ogg'),
  moneda: await cargar('moneda.ogg'),
};

function reproducir(buffer, { volumen = 1, pitch = 0 } = {}) {
  const src = ctx.createBufferSource(); // ¡de un solo uso!
  src.buffer = buffer;
  src.detune.value = pitch * 100;       // en cents
  const g = ctx.createGain();
  g.gain.value = volumen;
  src.connect(g).connect(ctx.destination);
  src.start();
  return src;
}

El AudioBuffer (los datos decodificados) se carga una sola vez y se reutiliza. El AudioBufferSourceNode en cambio es descartable: se crea uno nuevo cada vez que suena y después de stop() no se puede volver a arrancar. Es barato, se pueden crear cientos.

Arquitectura típica de un juego Un GainNode maestro, y debajo un bus por categoría (música, efectos, voces, interfaz), cada uno con su volumen para el menú de opciones. Los efectos de ambiente comparten un bus de reverb. Los sonidos con posición pasan por un PannerNode que se actualiza con la posición de la entidad en cada frame.

El reloj del audio: programar en el futuro

setTimeout y setInterval corren en el hilo principal: si el juego tarda en dibujar un frame o el recolector de basura se activa, se atrasan. Para música y ritmo se programan los sonidos un poco hacia adelante usando el reloj del audio: src.start(ctx.currentTime + 0.1).

Prendé los dos metrónomos y después activá el bloqueo del hilo principal (simula un juego que se traba). El de setTimeout se desarma; el programado sigue perfecto.

let proximo = ctx.currentTime;
setInterval(() => {                  // cada 25 ms miramos adelante
  while (proximo < ctx.currentTime + 0.1) {
    tic(proximo);                    // src.start(proximo)
    proximo += 0.25;                 // 240 BPM en corcheas
  }
}, 25);

Cada barra es un golpe: cuántos milisegundos se atrasó respecto del tiempo ideal. En rojo, más de 15 ms (ya se nota al oído).

Automatización de parámetros

Casi todo lo que se puede ajustar en un nodo (volumen, frecuencia, Q, tiempo de delay…) es un AudioParam. Además de asignarle .value, se le puede programar una curva en el tiempo que el navegador ejecuta con precisión de muestra, aunque el hilo principal esté ocupado. Así se hacen las envolventes, los fade in / fade out, los barridos de filtro y los cambios de pitch.

Y un nodo también puede conectarse a un parámetro: lfo.connect(filtro.frequency). Eso es modulación, la base de los efectos y los sintes que vimos.

Tip: nunca cambies gain.value de golpe mientras suena (hace "click"). Usá setTargetAtTime(valor, ctx.currentTime, 0.02) para un cambio suave.

La línea es la curva programada para osc.frequency; los puntos son el valor real que va leyendo el navegador mientras suena.

3. AudioWorklet: tu propio procesamiento

Los nodos nativos cubren casi todo, pero a veces necesitás un algoritmo propio: un bitcrusher, un sinte a medida, un detector de tono, un emulador de un chip de consola. Para eso está el AudioWorklet.

Tu código corre en el hilo de audio, separado del hilo principal donde corre el juego. El navegador llama a tu método process() una y otra vez, cada vez con un bloque de 128 muestras por canal (2,7 ms a 48 kHz). Tenés que llenar las salidas y devolver true para seguir vivo.

Como corre ~375 veces por segundo, adentro de process() no se crean objetos ni arrays (el recolector de basura produce cortes), no se usa el DOM y no se espera nada asincrónico. Los dos hilos se comunican con port.postMessage() y con AudioParams propios.

Es el reemplazo de ScriptProcessorNode, que está deprecado porque corría en el hilo principal.

// ---- archivo: ruido-processor.js (hilo de audio) ----
class RuidoProcessor extends AudioWorkletProcessor {
  static get parameterDescriptors() {
    return [{ name: 'volumen', defaultValue: 0.2,
              minValue: 0, maxValue: 1 }];
  }
  process(inputs, outputs, parameters) {
    const salida = outputs[0];             // [canal][muestra]
    const vol = parameters.volumen[0];
    for (const canal of salida)
      for (let i = 0; i < canal.length; i++) // 128 muestras
        canal[i] = (Math.random() * 2 - 1) * vol;
    return true;                           // seguir procesando
  }
}
registerProcessor('ruido', RuidoProcessor);
// ---- archivo: main.js (hilo principal) ----
const ctx = new AudioContext();
await ctx.audioWorklet.addModule('ruido-processor.js');

const ruido = new AudioWorkletNode(ctx, 'ruido');
ruido.connect(ctx.destination);

// controlar el parámetro como cualquier AudioParam
const vol = ruido.parameters.get('volumen');
vol.setTargetAtTime(0.5, ctx.currentTime, 0.1);

// mensajes en las dos direcciones
ruido.port.onmessage = (e) => console.log(e.data);
ruido.port.postMessage({ tipo: 'reset' });

Laboratorio: editá el procesador y escuchalo

El código de abajo se carga como módulo con addModule() (desde un Blob, sin archivo aparte) cada vez que apretás el botón. Los parameterDescriptors se convierten automáticamente en sliders. Probá cambiar números, romperlo, o escribir uno nuevo.
