Muestreo y profundidad de bits

El sonido es aire que cambia de presión de forma continua. La computadora no puede guardar algo continuo: lo mide cada tanto (muestreo) y redondea cada medición al escalón más cercano (cuantización). Esas dos decisiones definen la calidad y el peso de cada audio de tu juego.

La onda continua en ámbar, lo que guarda la computadora en cian

Frecuencia de muestreo (eje horizontal)

Cuántas veces por segundo medimos la señal. 44.100 Hz significa 44.100 números por segundo y por canal. Según el teorema de Nyquist–Shannon, con una frecuencia de muestreo fs solo podemos representar frecuencias de hasta fs / 2 (la frecuencia de Nyquist). El oído humano llega a unos 20 kHz, por eso el CD usa 44,1 kHz.

Si la señal tiene frecuencias por encima de fs / 2, no desaparecen: se disfrazan de otra frecuencia más grave. Eso es aliasing. Probá poner la señal en 7 kHz con muestreo de 8 kHz y la reconstrucción en "suave".

Profundidad de bits (eje vertical)

Con cuántos escalones guardamos cada medición. Con n bits hay 2ⁿ niveles posibles: 8 bits son 256 niveles, 16 bits son 65.536. La diferencia entre el valor real y el escalón elegido es el error de cuantización, y se escucha como ruido o "granulado".

Cada bit suma unos 6 dB de rango dinámico (la distancia entre el sonido más fuerte y el piso de ruido): 8 bits ≈ 48 dB, 16 bits ≈ 96 dB, 24 bits ≈ 144 dB.

Es lo mismo que pasa con los FPS de tu juego Una rueda que gira rápido filmada a 60 cuadros por segundo puede parecer que gira lento o para atrás. Es aliasing temporal: muestreás demasiado lento para lo rápido que cambia la cosa. En audio pasa exactamente lo mismo, pero lo escuchás en vez de verlo.

¿Qué hay realmente en memoria?

En la Web Audio API un sonido es un AudioBuffer: un Float32Array por canal con valores entre -1 y 1. No importa si el archivo original era de 8 o 16 bits, el navegador lo convierte a float de 32 bits a la frecuencia del AudioContext (normalmente 44.100 o 48.000 Hz).

Generar sonido desde cero es solamente llenar ese array con números:

const ctx = new AudioContext();
const sr = ctx.sampleRate;              // 44100 o 48000
const buf = ctx.createBuffer(1, sr * 2, sr); // 1 canal, 2 segundos
const data = buf.getChannelData(0);     // Float32Array

for (let i = 0; i < data.length; i++) {
  const t = i / sr;                      // en qué segundo cae la muestra i
  data[i] = 0.5 * Math.sin(2 * Math.PI * 440 * t);
}

const src = ctx.createBufferSource();
src.buffer = buf;
src.connect(ctx.destination);
src.start();

Y bajarle la calidad es igual de simple

Esto es todo el "bitcrusher" que estás escuchando arriba: retener cada muestra varias veces (baja el muestreo) y redondear a menos niveles (baja los bits).

function bitcrush(input, srOriginal, fsNueva, bits) {
  const out = new Float32Array(input.length);
  const paso = srOriginal / fsNueva;      // cada cuántas muestras medimos
  const niveles = Math.pow(2, bits) / 2;  // niveles por cada mitad (+ y -)
  let retenido = 0, proxima = 0;
  for (let i = 0; i < input.length; i++) {
    if (i >= proxima) {                   // ¡momento de medir!
      retenido = (Math.floor(input[i] * niveles) + 0.5) / niveles;
      proxima += paso;
    }
    out[i] = retenido;                    // sample and hold
  }
  return out;
}

Cuánto pesa el audio

Peso por segundo = frecuencia de muestreo × bits × canales. Con eso se entiende por qué los juegos comprimen la música.

Consejo práctico Comprimí la música (OGG/MP3/AAC) para que descargue rápido, pero acordate de que al decodificarla vuelve a ocupar ~22 MB por minuto en RAM. Para música larga conviene un elemento <audio> (que hace streaming) conectado con createMediaElementSource, y dejar los AudioBuffer para efectos cortos.
