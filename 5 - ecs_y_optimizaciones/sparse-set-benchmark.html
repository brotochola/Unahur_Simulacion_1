Sparse Set vs Dense Array

seecs implementa el almacenamiento de componentes con un sparse set: un arreglo disperso de índices más un arreglo denso y empaquetado de datos. Esta página porta ese mismo algoritmo a JavaScript y lo corre en tu navegador contra un arreglo denso indexado directamente (la alternativa obvia) y un par de contendientes extra, para ver en qué casos la indirección realmente vale la pena.

Cómo funciona

La idea del sparse set: en vez de guardar un valor por cada entidad posible (que desperdicia espacio e iteración cuando pocas entidades tienen el componente), se guardan dos arreglos. sparse[entidad] apunta a una posición dentro de dense[], que contiene solo los valores que realmente existen, bien empaquetados. Un tercer arreglo denseToEntity[] permite volver de una posición densa a su entidad original.

Sparse Set
sparse[entidad] → índice denso
dense[] (empaquetado)

Iterar recorre solo 4 celdas: las que existen.

Dense Array (directo)
data[entidad] — mismas 4 entidades

Iterar recorre las 8 celdas, saltando los huecos. Con millones de entidades y pocos componentes, esa diferencia se vuelve enorme.

Para borrar sin dejar huecos en dense[], seecs usa el clásico swap-and-pop: mueve el último elemento denso al lugar del que se borra y achica el arreglo en uno, en vez de correr todo lo que está después (como haría un splice). Así, insertar, leer, borrar e iterar terminan siendo O(1) por elemento — excepto iterar, que es O(cantidad real), no O(rango de entidades).

Configurá el benchmark

Se generan N entidades con datos, distribuidas al azar dentro de un "universo" de entidades posibles. La densidad controla qué fracción de ese universo tiene datos: bajarla simula un componente raro repartido entre muchas entidades — el caso de uso real que motiva al sparse set.

Costo estructural (memoria)

Esto no es un cronómetro — son cuentas directas sobre la última corrida del benchmark principal. La ventaja en velocidad de iteración del sparse set no es gratis: paga con un arreglo índice del tamaño del universo, aunque ese arreglo guarda enteros chicos, no los valores completos.

Corré el benchmark principal para ver esta comparación.

Algoritmo de referencia: sparse set de chrischristakis/seecs (arreglo disperso + arreglo denso + swap-and-pop al eliminar). La técnica en sí es clásica en la literatura de estructuras de datos y se usa en varios ECS (EnTT, seecs, etc.); acá está reimplementada en JS para este benchmark, no copiada del código C++ original.

Metodología: cada operación se mide con performance.now(), se repite N veces y se reporta la mediana para amortiguar el ruido del JIT y del recolector de basura. Los arreglos base se pre-dimensionan al tamaño del universo antes de medir, así la comparación aísla el patrón de acceso de cada estructura en vez del costo incidental de ir agrandando un arreglo de a poco.
