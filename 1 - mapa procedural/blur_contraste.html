Grid random → blur (promedio de vecinos)

Pasadas: 0

¿Qué está pasando acá?

1. Grid random

Cada celda arranca con un número random entre 0 y 1 (distribución uniforme, sin ninguna relación con sus vecinas). Ese número se pinta directamente como gris: 0 = negro, 1 = blanco. Por eso el resultado inicial es "estática" pura, tipo ruido de TV vieja — no hay ninguna estructura espacial, cada celda es independiente de las demás.

2. Blur = convolución con un kernel caja (box kernel)

El blur es el ejemplo clásico de convolución discreta. Para cada celda, en vez de mirar solo su propio valor, agarramos una "ventana" de 3x3 celdas centrada ahí (ella + sus 8 vecinas) y las promediamos. Eso es literalmente aplicar este kernel (matriz de pesos) y deslizarlo por toda la grilla: 

1/9  1/9  1/9
1/9  1/9  1/9
1/9  1/9  1/9

Cada peso vale 1/9 porque son 9 celdas y queremos el promedio (si sumáramos sin dividir, la imagen se iría toda a blanco). Esto es "normalizar el kernel": la suma de todos los pesos debe dar 1, así el brillo promedio de la imagen no cambia.

Al deslizar este kernel celda por celda, valores muy distintos entre vecinos se "contagian" y se acercan al promedio local. Repetir esta operación muchas veces (botón "Blur x10") es matemáticamente encadenar convoluciones, y por el teorema central del límite el resultado tiende a parecerse a una campana gaussiana suave — por eso después de varias pasadas la imagen se ve "borrosa" y sin bordes duros. El costo: los valores se van comprimiendo hacia el gris medio (0.5) y la imagen pierde contraste — todo se ve cada vez más plano.

3. Contraste: NO es convolución, es una transformación puntual (pointwise)

A diferencia del blur, que mezcla información entre celdas vecinas (por eso es convolución "espacial"), el botón de contraste opera cada celda en total aislamiento, sin mirar a sus vecinas. La fórmula es: 

nuevo_valor = (valor - 0.5) * factor + 0.5

Esto es una función afín (recta): restamos 0.5 para centrar en 0, escalamos por el factor (alejando el valor de 0 en ambas direcciones), y volvemos a centrar en 0.5. Con factor > 1, los valores por encima del gris medio se van más hacia el blanco, y los que están por debajo se van más hacia el negro — de ahí el contraste.

¿Cómo se conecta esto con la idea de convolución? Se puede pensar el contraste como un "caso degenerado" de convolución: si el kernel del blur reparte su peso entre 9 celdas (1/9 cada una), el contraste equivale a un kernel de un solo punto (delta de Dirac) con peso igual al factor, en vez de 1: 

[ 0    0    0  ]
[ 0  factor 0  ]
[ 0    0    0  ]

Convolucionar con este kernel no mezcla nada con los vecinos (todos los pesos fuera del centro son 0): simplemente re-escala cada celda por sí misma. Es el kernel "identidad" pero amplificado. Esta es la diferencia matemática clave: blur = kernel ancho, energía repartida entre vecinos (suaviza), contraste = kernel puntual, energía concentrada en el centro (exagera). Un blur real de "sharpening" (afilado) en procesamiento de imágenes combina ambas ideas: resta una versión borrosa de la imagen a la imagen original amplificada (esto se llama unsharp masking), lo cual sí es una convolución con un kernel que tiene un centro grande positivo y vecinos negativos.

4. Normalizar (estirar min-max)

Esta operación tampoco es convolución — es aún más global que el contraste: mira todos los valores de la grilla, encuentra el mínimo y el máximo actuales, y estira ese rango para que ocupe todo el intervalo [0,1] de nuevo: 

nuevo_valor = (valor - min) / (max - min)

Es especialmente útil después de varias pasadas de blur, porque el blur no solo suaviza sino que además comprime el rango dinámico (los valores se acercan todos al promedio global). Normalizar "recupera" el contraste perdido sin inventar información nueva: solo reescala lo que ya está ahí. A diferencia del botón de contraste (que usa un factor fijo elegido a mano), normalizar se auto-ajusta según los datos reales de cada momento.
