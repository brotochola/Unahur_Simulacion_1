Monte Carlo Tree Search

¿Cómo hace una computadora para jugar bien a un juego si nadie le programó una estrategia? Una respuesta sorprendentemente buena: imaginando partidas al azar. Para cada jugada posible, juega cientos de partidas con movimientos aleatorios hasta el final y se fija cuál gana más seguido. Es Montecarlo aplicado a decidir, y con un árbol encima se vuelve una de las ideas más potentes de la IA de juegos.

Primer intento: Montecarlo plano

Para cada jugada legal, jugá N partidas al azar a partir de ahí y contá victorias (un empate vale medio punto). Elegí la jugada con mejor porcentaje. No hace falta saber nada del juego más allá de las reglas: qué jugadas son legales y quién ganó.

Probá la posición trampa: le toca a O, y X amenaza con completar la columna del medio. Cualquier persona tapa abajo al medio. Montecarlo plano, en cambio, prefiere una esquina. ¿Por qué? Porque en sus partidas imaginarias X juega al azar y muchas veces no completa la línea. Montecarlo plano asume que el rival es tonto.

MCTS: gastar las simulaciones donde importa

MCTS arregla los dos problemas del método plano: reparte mal las simulaciones (le da lo mismo a jugadas obviamente malas que a las buenas) y no mira más allá de un movimiento. Construye de a poco un árbol de partidas, y cada iteración tiene cuatro fases:

  1. Selección. Desde la raíz, bajar por el árbol eligiendo en cada nodo el hijo con mejor puntaje UCB (abajo), hasta llegar a un nodo que todavía tiene jugadas sin probar.
  2. Expansión. Agregar un hijo nuevo con una de esas jugadas.
  3. Simulación (playout). Desde ahí, jugar al azar hasta el final. Es el Montecarlo.
  4. Retropropagación. Subir por el camino sumando una visita a cada nodo y una victoria a los nodos del jugador que ganó.

La clave está en la selección. Hay que balancear dos cosas: explotar (seguir probando la jugada que viene ganando) y explorar (darle chances a las que se probaron poco, por si tuvieron mala suerte). La fórmula UCB1 suma las dos:

UCB = victorias / visitas + c · √( ln(visitas del padre) / visitas )  // c ≈ 1,4

El primer término es el promedio de Montecarlo. El segundo es un premio por incertidumbre: crece para los hijos con pocas visitas, y el ln hace que nunca deje de explorar del todo. Como el árbol pone al rival a elegir su mejor jugada en sus niveles, MCTS deja de asumir que el rival juega al azar.

¿Qué estoy viendo?
  • Arriba: la raíz (la posición actual). Fila del medio: cada jugada posible de O, con victorias/visitas, el porcentaje y su puntaje UCB. Verde: la más visitada, la que elegiría.
  • Puntos de abajo: las respuestas de X a cada jugada; el tamaño es la cantidad de visitas.
  • En naranja, el camino de la iteración actual. Abajo a la derecha, la partida al azar (playout) y su resultado.
  • Probá: "Fase siguiente" varias veces para ver las 4 fases, y después +1.000 para ver que termina eligiendo la casilla 7.

function mcts(estadoRaiz, iteraciones, c = 1.4) {
  const raiz = nodo(null, null, estadoRaiz);
  for (let it = 0; it < iteraciones; it++) {
    let n = raiz, s = estadoRaiz.clonar();
    // 1. selección
    while (n.sinProbar.length === 0 && n.hijos.length > 0) {
      n = maxPor(n.hijos, h => h.W / h.N + c * Math.sqrt(Math.log(n.N) / h.N));
      s.jugar(n.jugada);
    }
    // 2. expansión
    if (n.sinProbar.length > 0) {
      const j = sacarAlAzar(n.sinProbar);
      s.jugar(j);
      n = agregarHijo(n, j, s);              // guarda quién hizo la jugada
    }
    // 3. simulación
    while (!s.termino()) s.jugar(alAzar(s.jugadas()));
    const g = s.ganador();
    // 4. retropropagación
    for (; n; n = n.padre) {
      n.N++;
      if (g === 'empate') n.W += 0.5; else if (g === n.quienJugo) n.W += 1;
    }
  }
  return maxPor(raiz.hijos, h => h.N).jugada;  // la más visitada, no la de mejor promedio
}

Al final se elige el hijo más visitado: es el que MCTS investigó más y en el que más confía. Y el algoritmo se puede cortar en cualquier momento, después de 100 iteraciones o de 50 ms: más tiempo = mejor juego. Es el √N de Montecarlo convertido en dificultad.

Jugá contra MCTS

Cuatro en línea, sin una sola regla de estrategia programada: la compu solo sabe qué jugadas son legales y cuándo alguien ganó. Con 10 simulaciones por jugada le ganás fácil. Con 5.000, no tanto. Las barras muestran qué miró la compu en su última jugada.

En juegos AlphaGo (2016) le ganó a Lee Sedol, uno de los mejores jugadores de Go del mundo, con MCTS, reemplazando las partidas al azar por redes neuronales que estiman quién va ganando y qué jugadas conviene mirar; AlphaZero aprendió así ajedrez, shogi y Go desde cero. En juegos comerciales, la IA de campaña de Total War: Rome II usa MCTS para planificar. En juegos de cartas con información oculta se usa determinización: se reparten al azar las cartas que no se ven (más Montecarlo) y se corre MCTS sobre cada reparto.
Para el proyecto Si tu juego es por turnos y el estado se puede copiar y simular rápido, tenés una IA en 50 líneas, y el selector de dificultad sale gratis: es la cantidad de simulaciones. Funciona peor en tiempo real o cuando simular una partida entera es caro; ahí se cortan los playouts antes del final y se usa una heurística para estimar quién va ganando.

Cierre de la unidad

Todo lo de hoy sale de dos ideas. Montecarlo: cuando no sabés calcular algo, simulalo muchas veces y mirá la distribución, sabiendo que el error baja como 1/√N. Eventos discretos: si lo que importa son los momentos en que algo cambia, poné esos momentos en una cola de prioridad y hacé saltar el reloj. Las dos juntas sirven para decidir cuántas cajas abrir, balancear un drop, poner al día una colonia o elegir la próxima jugada.
