Poisson disk sampling

Querés poner 300 árboles en un mapa. Con Math.random() para x e y, algunos quedan encimados y en otras zonas aparecen claros enormes sin ningún árbol. El ojo lo lee como un error. Lo que buscamos es azar parejo: puntos al azar, pero que respeten una distancia mínima entre sí.

¿Qué es?

Un conjunto de puntos Poisson disk es un conjunto de puntos al azar que cumple una sola regla: ningún par de puntos puede estar a menos de una distancia r. Otra forma de verlo: cada punto que ponés "prohíbe" un círculo de radio r a su alrededor, y ahí no puede caer el centro de ningún otro punto.

El nombre tiene dos partes:

  • Poisson: en matemática, puntos tirados completamente al azar, cada uno sin saber nada de los otros (como los dardos del capítulo de Montecarlo), se llaman un proceso de Poisson. Es nuestro punto de partida.
  • Disk (disco): a ese azar le agregamos el círculo prohibido alrededor de cada punto.

La forma más directa de fabricarlo es literalmente esa: tirar dardos al azar y descartar los que caen en zona prohibida. Probalo acá: tocá el panel para poner puntos a mano, o tirá dardos al azar.

Dardos con una regla · círculo rojo: zona prohibida (radio r) de cada punto · tocá para poner un punto
¿Qué estoy viendo?
  • Puntos blancos: puntos aceptados. Círculo rojo alrededor de cada uno: la zona prohibida, de radio r.
  • Al tirar un dardo: círculo verde si entró, cruz roja si cayó en zona prohibida y se descartó.
  • Franja de abajo: cada barra es el porcentaje de rechazados en un grupo de 50 dardos. Va subiendo hasta casi 100% cuando el panel se llena.
  • Probá: "Lluvia" con muchos dardos por segundo y mirá cuándo deja de entrar todo.

Al principio casi todos los dardos entran. A medida que el panel se llena, la zona libre se achica y casi todos caen en zona prohibida: el porcentaje de rechazo sube hasta casi 100%. Cuando ya no entra ningún punto más, el conjunto está lleno (los matemáticos dicen maximal), y eso tiene una consecuencia importante: tampoco quedan huecos grandes, porque en cualquier hueco de más de r entraría otro punto.

Esas son las dos propiedades que buscábamos para los árboles: no hay puntos encimados (por la distancia mínima) y no hay claros vacíos (porque está lleno). Y como cada punto sigue cayendo al azar, no se forma ningún patrón regular.

Tres formas de repartir puntos

Comparemos con las alternativas. Los tres paneles tienen la misma cantidad de puntos. Alrededor de cada punto se dibuja un disco de radio r/2: si dos discos se pisan, esos dos puntos están a menos de r y se marcan en rojo. Abajo de cada panel: cuántos puntos tienen un vecino demasiado cerca, y cuál es la distancia del par más cercano, medida en unidades de r (1,00·r significa que se respeta la regla).

Poisson disk
  • Uniforme (Math.random() para x y para y). Cada punto ignora a los demás. Por pura casualidad algunos caen pegados (los rojos) y quedan zonas vacías. Tiene grumos y huecos.
  • Grilla con jitter. Se arma una grilla y cada punto se mueve un poco al azar dentro de su casilla. No quedan huecos grandes porque hay uno por casilla, pero dos puntos de casillas vecinas igual pueden quedar pegados, y si mirás de lejos se adivinan las filas y columnas.
  • Poisson disk. Ningún punto rojo, ningún hueco grande y ningún patrón. Se ve como un bosque de verdad, y no es casualidad: en la naturaleza las cosas compiten por espacio (los árboles por luz, las células por lugar), así que terminan separadas por una distancia mínima. Hasta los conos de la retina (las células que detectan color) están repartidos con un patrón muy parecido.

En gráficos a este tipo de patrón se le dice ruido azul (blue noise), por analogía con los colores de ruido de la unidad 8. El ruido azul tiene poca variación "grave" (nada de grumos ni huecos grandes) y toda su variación es de detalle fino, de punto a punto. Por eso, mirado de lejos, se ve parejo.

El algoritmo de Bridson

Tirar dardos y descartar, como hicimos arriba, funciona, pero se vuelve lentísimo al final: con el panel casi lleno hay que tirar cientos de dardos para que entre uno, y nunca sabés si ya está lleno o tuviste mala suerte. Robert Bridson publicó en 2007 un método que crece desde adentro hacia afuera y prueba candidatos solo cerca de puntos que ya existen:

  1. Poné un primer punto al azar y agregalo a la lista de activos.
  2. Elegí un activo al azar y probá hasta k candidatos (típicamente 30) en el anillo entre r y 2r alrededor suyo.
  3. Un candidato sirve si no hay ningún punto a menos de r. Si sirve, se agrega y queda activo.
  4. Si ninguno de los k sirve, ese punto ya está rodeado: sale de la lista de activos.
  5. Repetí hasta que no queden activos.

El truco de velocidad es una grilla de fondo con celdas de lado r/√2. La diagonal de una celda mide r, así que en cada celda entra a lo sumo un punto. Para saber si un candidato está libre, alcanza con mirar las 5×5 celdas vecinas: un costo constante, sin recorrer todos los puntos. Es el mismo spatial hash que usamos para los boids.

Bridson paso a paso · ● activo · ● terminado · + candidato aceptado · × rechazado
¿Qué estoy viendo?
  • Naranja: puntos activos (todavía pueden tener vecinos nuevos). Celeste: puntos terminados.
  • Anillo naranja: la zona entre r y 2r alrededor del activo elegido, donde se prueban candidatos.
  • Cruces: cada candidato. Verde, aceptado; rojo, rechazado por tener un punto a menos de r.
  • Grilla de fondo: celdas de r/√2. En cada celda entra a lo sumo un punto.
  • Probá: "Pasos por cuadro" en 1 cada 20 para seguirlo con calma, y después a 200 para verlo crecer.
function poissonDisk(W, H, r, k = 30, rnd = Math.random) {
  const cell = r / Math.SQRT2, gw = Math.ceil(W / cell), gh = Math.ceil(H / cell);
  const grid = new Int32Array(gw * gh).fill(-1);       // índice del punto en cada celda
  const pts = [], active = [];
  const add = (x, y) => { pts.push([x, y]); active.push(pts.length - 1);
    grid[Math.floor(y / cell) * gw + Math.floor(x / cell)] = pts.length - 1; };
  const libre = (x, y) => {
    const cx = Math.floor(x / cell), cy = Math.floor(y / cell);
    for (let j = Math.max(0, cy - 2); j <= Math.min(gh - 1, cy + 2); j++)
      for (let i = Math.max(0, cx - 2); i <= Math.min(gw - 1, cx + 2); i++) {
        const p = grid[j * gw + i];
        if (p >= 0 && (pts[p][0] - x) ** 2 + (pts[p][1] - y) ** 2 < r * r) return false;
      }
    return true;
  };
  add(rnd() * W, rnd() * H);
  while (active.length) {
    const ai = Math.floor(rnd() * active.length), [px, py] = pts[active[ai]];
    let ok = false;
    for (let t = 0; t < k && !ok; t++) {
      const a = rnd() * 2 * Math.PI, d = r * Math.sqrt(1 + 3 * rnd());   // parejo en el anillo [r, 2r]
      const x = px + d * Math.cos(a), y = py + d * Math.sin(a);
      if (x >= 0 && y >= 0 && x < W && y < H && libre(x, y)) { add(x, y); ok = true; }
    }
    if (!ok) { active[ai] = active[active.length - 1]; active.pop(); }  // sacar sin correr el array
  }
  return pts;
}

Fijate en r * Math.sqrt(1 + 3 * rnd()): es el mismo truco de la raíz del capítulo anterior, para que los candidatos se repartan parejo por el área del anillo y no se amontonen en el borde de adentro.

Densidad variable: un bosque con claros

Si r depende de la posición, la densidad cambia por zonas. Acá r sale de un ruido suave como el de la unidad 1: donde el ruido es bajo, r es chico y el bosque es denso; donde es alto, r es grande y se abren claros. Hay que agrandar la búsqueda en la grilla para cubrir el r más grande.

¿Qué estoy viendo?

  • El radio sale de un ruido suave: donde el ruido es bajo, los árboles quedan pegados (bosque denso); donde es alto, separados (claros).
