La cola de eventos

El loop de un simulador de eventos discretos hace siempre lo mismo: sacar el evento más próximo y agendar otros. Con 10 eventos cualquier lista sirve. En el Simulador de Comunidad 3000 AC de la carpeta de la unidad (una aldea prehistórica donde cada persona come, trabaja, se hace amiga de otras y forma pareja, todo manejado con eventos; lo vemos en el capítulo 7) hay miles agendados a la vez, y en un juego con física por eventos (capítulo 7) puede haber cientos de miles. Ahí la estructura de datos lo decide todo.

Qué es un heap

Un min-heap es un árbol binario con una sola regla: cada padre es menor o igual que sus hijos. No dice nada sobre hermanos ni primos, así que no está ordenado, pero garantiza que el mínimo está siempre en la raíz. Además el árbol está siempre completo (se llena nivel por nivel, de izquierda a derecha), y por eso entra en un array común sin punteros:

padre de i(i − 1) >> 1 hijos de i2i + 1  y  2i + 2
  • Insertar: va al final del array (la primera hoja libre) y sube intercambiándose con su padre mientras sea menor (sift up).
  • Sacar el mínimo: se saca la raíz, el último elemento pasa a la raíz y baja intercambiándose con el menor de sus hijos (sift down).

Las dos operaciones recorren a lo sumo la altura del árbol, que es log₂ n: con un millón de eventos, unos 20 pasos.

Min-heap en vivo · arriba el árbol, abajo el mismo heap como array · ■ comparando · ■ recién intercambiado
¿Qué estoy viendo?
  • Arriba: el heap dibujado como árbol. Abajo: el mismo heap como array, con el índice de cada casilla.
  • Naranja: los nodos que se están comparando. Verde: los que se acaban de intercambiar.
  • Abajo del panel, los valores que se fueron sacando: siempre salen de menor a mayor.
  • Probá: "Insertar" un 1 y mirá cómo sube hasta la raíz.
class MinHeap {
  constructor(cmp = (a, b) => a - b) { this.a = []; this.cmp = cmp; }
  push(x) {
    const a = this.a; a.push(x); let i = a.length - 1;
    while (i > 0) {                                   // sift up
      const p = (i - 1) >> 1;
      if (this.cmp(a[i], a[p]) >= 0) break;
      [a[i], a[p]] = [a[p], a[i]]; i = p;
    }
  }
  pop() {
    const a = this.a, top = a[0], last = a.pop();
    if (a.length) {
      a[0] = last; let i = 0;
      for (;;) {                                      // sift down
        const l = 2 * i + 1, r = l + 1; let m = i;
        if (l < a.length && this.cmp(a[l], a[m]) < 0) m = l;
        if (r < a.length && this.cmp(a[r], a[m]) < 0) m = r;
        if (m === i) break;
        [a[i], a[m]] = [a[m], a[i]]; i = m;
      }
    }
    return top;
  }
}

Heapify y heap sort

Si ya tenés todos los elementos, no hace falta insertarlos de a uno (n·log n). Heapify arma el heap de abajo hacia arriba: recorre los nodos internos desde el último hasta la raíz y hace sift down de cada uno. Parece n·log n, pero la mitad de los nodos son hojas que no se mueven, un cuarto baja un nivel, un octavo dos... y la suma da O(n).

Con un heap, ordenar es fácil: heap sort. Se arma un max-heap, el máximo (la raíz) se intercambia con el último lugar, ese lugar queda "cerrado" y se repite con el resto. Ordena en el mismo array en O(n log n) garantizado y sin memoria extra.

Heapify + heap sort (max-heap) · en gris, la parte ya ordenada
¿Qué estoy viendo?
  • Arriba el árbol, abajo el array con barras de altura proporcional al valor.
  • "Heapify" acomoda el array hasta que cada padre sea mayor que sus hijos.
  • "Heap sort" va sacando la raíz (el máximo) al final del array; esa parte queda en gris, ya ordenada.

Medirlo: un DES con n eventos agendados

La prueba típica de una cola de eventos (el hold model): se cargan n eventos y después se repite n veces "sacar el próximo y agendar uno nuevo un rato más tarde", que es exactamente lo que hace un simulador.

Empates: el detalle que rompe la reproducibilidad

¿Qué pasa si dos eventos tienen el mismo tiempo? Un heap no es estable: entre iguales, el orden de salida depende de cómo quedó armado el árbol, no del orden en que se agendaron. En un juego por turnos eso puede decidir quién actúa primero, y si cambia entre corridas, ya no podés reproducir un bug ni un replay. La solución es un contador de secuencia como segundo criterio. Así lo hace el Simulador de Comunidad 3000 AC (carpeta Discrete_event_sim/simulador de historia de pueblo, archivo src/Simulation.js):

this.eventQueue = new MinHeap((a, b) => {
  const d = a.time - b.time;
  return d !== 0 ? d : a.seq - b.seq;     // a igual tiempo, el que se agendó primero
});
scheduleEvent(ev) { ev.seq = this._eventSeq++; this.eventQueue.push(ev); }
