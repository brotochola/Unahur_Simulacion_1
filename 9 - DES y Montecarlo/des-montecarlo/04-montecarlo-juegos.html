Montecarlo en juegos

Un diseñador vive haciéndose preguntas como "¿esto es justo?", "¿cuánto tarda un jugador en conseguir la espada?" o "¿está roto este personaje?". Casi ninguna tiene una fórmula cómoda, pero todas se responden igual: simulá un millón de veces y mirá la distribución.

El azar puro no se siente justo

Un personaje tiene 25% de chance de crítico. Con azar puro, en cada golpe se tira Math.random() < 0.25, sin importar lo que pasó antes. En promedio da 1 crítico cada 4 golpes, pero las rachas pueden ser feas. La chance de que 10 golpes seguidos salgan sin crítico es 0,75¹⁰ ≈ 5,6%, más o menos una de cada 18 veces. Y un jugador pega miles de golpes por partida, así que le va a pasar seguido. El jugador no ve el 25%: ve la racha, y la vive como un bug o como una trampa.

La idea de PRD: que la chance vaya creciendo

Dota 2 y Warcraft III usan una técnica llamada pseudo-random distribution (PRD). En vez de una chance fija, la chance de crítico crece con cada golpe que no fue crítico, y cuando sale un crítico vuelve a empezar desde abajo. Así, cuanto más tiempo pasa sin crítico, más probable es el próximo, y las rachas largas casi desaparecen.

La regla es simple. Se elige un número fijo, C, que es "cuánto sube la chance por golpe". Contando los golpes desde el último crítico:

chance en el golpe n = C · n  // n = golpes desde el último crítico (1, 2, 3…)

Para un 25% nominal, C resulta ser 8,5%. El primer golpe después de un crítico tiene 8,5% de chance, el segundo 17%, el tercero 25,4%, el cuarto 33,9%… y el duodécimo pasaría el 100%, así que nunca hay más de 11 golpes seguidos sin crítico.

¿Por qué C es 8,5% y no 25%? Porque la chance va subiendo: si arrancara en 25%, el promedio terminaría mucho más alto que 25%. Hay que arrancar más bajo para que, contando todo, salga exactamente un crítico cada 4 golpes. El problema es encontrar ese C. Hay una fórmula, pero es incómoda. Lo práctico es probar un C, simular cien mil golpes, medir qué porcentaje salió crítico y corregir. Eso es Montecarlo. La búsqueda automática hace lo que harías a mano: si la tasa medida da más alta que 25%, baja C; si da más baja, sube C. Cada vez parte el rango a la mitad (búsqueda binaria), así que en una docena de pasos llega. Como cada medición tiene un poco de ruido (es Montecarlo), el resultado puede variar en el segundo decimal entre corridas; el valor exacto es 8,47%. // PRD: la chance crece con cada fallo y se resetea al acertar
const C = 0.085;          // para un 25% nominal
let fallos = 0;
function esCritico() {
  fallos++;
  if (Math.random() < C * fallos) { fallos = 0; return true; }
  return false;
}

Tetris y la bolsa de 7

Los Tetris modernos no eligen piezas al azar puro: meten las 7 piezas en una bolsa, la mezclan y las van sacando. Cuando la bolsa se vacía, se rellena. Así, entre dos palos largos (la pieza I) hay como máximo 12 piezas. Con azar puro, la "sequía" puede durar 40 o más.

La misma idea se usa en los mazos de los roguelikes (Slay the Spire, Balatro): "¿con qué probabilidad tengo el combo en mano en el turno 3?" se responde mezclando el mazo un millón de veces.

"Drop del 1%": el promedio miente

Si un ítem cae con probabilidad p por enemigo, el promedio de intentos es 1/p: con 1%, 100 enemigos. Pero la probabilidad de no tenerlo después de n intentos es (1 − p)ⁿ, y a los 100 intentos todavía el 37% de los jugadores no lo tiene. Uno de cada cien va a necesitar más de 460. Los juegos con gacha o loot boxes agregan pity: si llegaste a N intentos sin premio, el siguiente es seguro. Eso corta la cola larga de la distribución.

Al diseñar no conviene mirar el promedio sino los percentiles: ¿qué le pasa al 10% con peor suerte? Esa gente es la que abandona el juego, y el pity está pensado para ella.

function duelo(A, B, empiezaA) {
  const vida = [A.vida, B.vida], u = [A, B];
  let t = empiezaA ? 0 : 1, turnos = 0;
  while (vida[0] > 0 && vida[1] > 0) {
    const atk = u[t];
    if (Math.random() < atk.precision) {
      let dmg = atk.dmin + Math.random() * (atk.dmax - atk.dmin);
      if (Math.random() < atk.critico) dmg *= 2;
      vida[1 - t] -= dmg;
    }
    t = 1 - t; turnos++;
  }
  return { ganaA: vida[0] > 0, turnos };
}
// ganaA en 20.000 duelos → % de victorias ± 1,96·√(p(1−p)/N)

Estrategias de casino: validar con simulación

La martingala dice: apostá 1 a rojo; si perdés, duplicá; cuando ganes, recuperás todo y ganás 1. Parece infalible, y en una sesión corta casi siempre funciona. Pero la ruleta tiene el 0, que hace que cada apuesta pierda en promedio 2,7%, y una racha de 8 rojos perdidos te pide apostar 256. Montecarlo muestra la verdad en segundos: la mayoría de las sesiones llega a la meta ganando de a 1, pero una parte grande lo pierde todo de golpe, y el promedio queda en negativo.
