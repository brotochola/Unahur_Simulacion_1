Azar con forma

Math.random() devuelve un número entre 0 y 1, y cualquier valor tiene la misma chance de salir. Pero en un juego casi nada funciona así: la altura de los NPCs se junta alrededor de un promedio, el tiempo entre enemigos suele ser corto y a veces muy largo, la suma de dos dados da 7 mucho más que 2. Este capítulo trata de cómo describir esas "formas" del azar y cómo fabricarlas a partir de Math.random().

Pseudoaleatorio: azar que se puede repetir

Una computadora no tira dados. Un generador pseudoaleatorio (PRNG) es una función determinista que guarda un número de estado, lo revuelve y devuelve el resultado. Los números parecen al azar, pero si arrancás del mismo estado inicial, la semilla, sale exactamente la misma secuencia.

// mulberry32: pocas líneas, 32 bits de estado, alcanza y sobra para un juego
function mulberry32(seed) {
  let a = seed >>> 0;
  return function () {
    a = (a + 0x6D2B79F5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;   // -> [0, 1)
  };
}
const rnd = mulberry32(1234);
rnd(); rnd(); rnd();   // siempre los mismos tres números
Un mundo por semilla · el mapa entero sale de una sola secuencia de números
En juegos Minecraft, No Man's Sky o Spelunky generan mundos enteros a partir de una semilla, y los "desafíos diarios" usan la fecha como semilla para que todos jueguen el mismo nivel. Un replay no guarda la partida: guarda la semilla y los inputs del jugador, y vuelve a simular. Lo mismo hacen los juegos de estrategia en red (lockstep): cada máquina simula por su cuenta y solo se mandan los inputs. Y un bug que aparece "a veces" se vuelve reproducible si sabés la semilla.
Una semilla por sistema. Si el loot y la generación del mapa comparten el mismo generador, agregar una tirada de loot cambia el mapa. Lo prolijo es tener un generador para cada cosa (rngMapa, rngLoot, rngIA), todos derivados de la semilla principal.

¿Qué es una distribución?

Pedile a un generador 10.000 números y anotalos. Cada número por separado es impredecible, pero el conjunto no: hay valores que salen muy seguido y otros que casi nunca. La distribución es justamente eso: la descripción de qué valores salen y con qué frecuencia. No te dice qué va a salir en la próxima tirada; te dice cómo se ven muchas tiradas juntas.

La forma más fácil de verla es un histograma: se divide el rango de valores en franjas, se cuenta cuántos números cayeron en cada franja y se dibuja una barra con esa cantidad. Barra alta = valores que salen seguido.

Fábrica de histogramas · elegí un generador y tirá · cada bolita cae en la franja de su valor

Cosas para probar en clase:

  • Un dado: con pocas tiradas las barras salen desparejas; con miles, quedan todas iguales. Esa forma plana se llama uniforme: todos los valores con la misma chance. Math.random() también es uniforme, entre 0 y 1.
  • Dos dados sumados: el 7 sale seis veces más que el 2. No es que los dados "prefieran" el 7: hay 6 combinaciones que suman 7 (1+6, 2+5, 3+4, 4+3, 5+2, 6+1) y una sola que suma 2 (1+1).
  • Espera exponencial y normal: las dos formas que más vamos a usar. Las explicamos más abajo.

Con pocas tiradas el histograma es ruidoso. Con muchas se estabiliza en una forma que ya no cambia: esa forma límite es la distribución.

Dos números que resumen una distribución

  • Media (el promedio): dónde está el centro. Se suman todos los valores y se divide por la cantidad. En el histograma de arriba es la línea vertical.
  • Desvío estándar: cuánto se desparraman los valores alrededor de la media. Es, más o menos, la distancia típica entre un valor y el promedio. Desvío chico: casi todos cerca de la media. Desvío grande: valores muy desparramados. En el histograma es la franja sombreada, que va de media − desvío a media + desvío.
const media  = xs.reduce((a, x) => a + x, 0) / xs.length;
// para cada valor: cuánto se aleja de la media, al cuadrado (así no se cancelan + y −);
// se promedia y se saca la raíz para volver a las unidades originales
const desvio = Math.sqrt(xs.reduce((a, x) => a + (x - media) ** 2, 0) / xs.length);
// (el desvío al cuadrado se llama "varianza"; aparece en algunas fórmulas)

Dos dados sumados tienen media 7 y desvío 2,4: la mayoría de las tiradas cae entre 4,6 y 9,4. Un dado solo tiene media 3,5 y desvío 1,7.

La normal (campana de Gauss)

La normal es la distribución con forma de campana: la mayoría de los valores cerca del promedio, cada vez menos a medida que te alejás, y simétrica para los dos lados. Toda normal queda definida con solo dos números: la media (dónde está el pico) y el desvío (qué tan ancha es la campana). Y cualquier normal cumple siempre la misma regla:

68% a menos de 1 desvío · 95% a menos de 2 · 99,7% a menos de 3  // la regla 68-95-99,7
Altura de los NPCs de un pueblo · normal con la media y el desvío que elijas · abajo, 40 NPCs generados con ella

Con media 170 cm y desvío 8 cm, 2 de cada 3 NPCs miden entre 162 y 178, y uno de cada 370 mide más de 194 o menos de 146. Si las alturas salieran de una uniforme entre 146 y 194, el pueblo tendría tantos gigantes como gente normal.

¿Por qué aparece en todos lados? Sumar azar

La altura de una persona es la suma de muchísimos efectos chicos (genes, alimentación, etc.). El error de un tirador, la suma de varias tiradas de dados, el tiempo total de varias tareas: todo eso son sumas de cosas al azar. Y pasa algo notable: si sumás varios números al azar, la suma tiene forma de campana, sin importar la forma de cada uno por separado. Se llama teorema central del límite. Con un dado la distribución es plana; con dos, un triángulo; con tres ya parece una campana.

Cómo generar una normal

Math.random() es uniforme, no normal. La forma más simple de conseguir una normal usa lo que acabamos de ver: sumar 12 uniformes. Cada uniforme entre 0 y 1 tiene media 0,5, así que la suma tiene media 6; restándole 6 queda centrada en 0. Y con 12 justo da desvío 1 (por eso 12 y no otro número). A esa normal "estándar" (media 0, desvío 1) se la estira y se la corre para tener la media y el desvío que quieras:

function normalAprox() {               // media 0, desvío 1 (aproximada)
  let s = 0;
  for (let i = 0; i < 12; i++) s += Math.random();
  return s - 6;
}
const altura = 170 + 8 * normalAprox();   // media 170 cm, desvío 8 cm

Es una aproximación: nunca da valores más allá de ±6 desvíos y cuesta 12 llamadas a Math.random(), pero para un juego alcanza. Existe una receta exacta, Box-Muller, que vemos al final del capítulo porque usa un truco que todavía no presentamos.

En juegos Las stats con 3d6 de Dungeons & Dragons (sumar tres dados) hacen que los valores extremos (3 o 18) sean rarísimos, cosa que un dado de 16 caras no logra. En Catan, el 7 del ladrón sale 1 de cada 6 tiradas porque es la suma más probable de 2d6. Para la altura de NPCs, la puntería de la IA o la variación del daño, una normal se ve más natural que una uniforme: casi todos cerca del promedio y pocos raros.

De uniforme a cualquier forma: la transformada inversa

Sumar uniformes da campanas, pero ¿y si querés otra forma, como la exponencial? Hay una técnica general que sirve para cualquier distribución. Antes hace falta una herramienta más.

La acumulada

La función acumulada F(x) responde una sola pregunta: ¿qué fracción de los valores es menor o igual a x? Con un dado, F(2) = 2/6, porque salen 1 o 2 en 2 de cada 6 tiradas, y F(6) = 1, porque siempre sale 6 o menos. Siempre arranca en 0, siempre sube y termina en 1. Donde se juntan muchos valores la acumulada sube empinada; donde hay pocos, sube despacio.

La exponencial

La exponencial describe cuánto hay que esperar hasta que pase algo que ocurre al azar a un ritmo constante: el próximo cliente, el próximo meteorito, la próxima llamada. Su único parámetro es la media, el tiempo de espera promedio. Su acumulada es:

F(x) = 1 − e^(−x / media)

Por ejemplo, con media 10 segundos, F(10) ≈ 0,63: el 63% de las esperas duran menos que el promedio. Suena raro, pero es porque hay muchas esperas cortas y unas pocas muy largas que tiran el promedio para arriba.

La idea: usar la acumulada al revés

Tirá un uniforme u entre 0 y 1 y buscá el x que tiene F(x) = u. Ese x sale con la distribución que querías. ¿Por qué? Supongamos que la acumulada dice que el 30% de los valores está por debajo de cierto x₃₀. El uniforme u cae por debajo de 0,3 exactamente el 30% de las veces, y en esos casos el x que encontramos queda por debajo de x₃₀. O sea, x cae por debajo de x₃₀ el 30% de las veces, que es lo que pide la distribución. Lo mismo vale para cualquier porcentaje.

Para la exponencial se puede despejar x de la fórmula de arriba, y queda una línea de código:

x = −media · ln(1 − u)  // u = Math.random()
Transformada inversa, gota a gota · el uniforme cae en el eje vertical, rebota en la acumulada y baja al histograma
arriba: la acumulada F(x)abajo: histograma de los x · curva blanca: la forma ideal

Los u están repartidos parejo en el eje vertical, pero la acumulada es empinada a la izquierda, así que muchos u distintos terminan en valores chicos de x. Por eso la exponencial tiene muchas esperas cortas y pocas largas. La curva blanca de abajo (la densidad) es la forma a la que tiende el histograma con infinitas muestras.

En juegos: ¿spawn cada 10 s o "en promedio" cada 10 s? Un enemigo que aparece cada 10 segundos exactos se vuelve predecible: el jugador cuenta. Con esperas exponenciales de media 10 s, el ritmo promedio es el mismo, pero a veces caen dos casi juntos y a veces hay un respiro largo. La exponencial además no tiene memoria: haber esperado 8 segundos no hace más probable que el próximo llegue ya. Es el modelo de "cosas que pasan al azar", y es la base del simulador de eventos discretos del capítulo 5.

Azar en 2D: el error del radio

Querés repartir impactos de escopeta de forma pareja dentro de un círculo de radio R. Lo primero que se le ocurre a cualquiera: ángulo al azar y radio al azar, r = R·u. Pero eso amontona los impactos en el centro. ¿Por qué? Pensá el círculo como anillos. Un anillo cerca del borde es mucho más largo que uno cerca del centro, así que para que todo quede parejo tiene que recibir más impactos. Con R·u, todos los anillos reciben la misma cantidad, y los de adentro, que son chiquitos, quedan saturados.

La solución es la transformada inversa otra vez. ¿Qué fracción del círculo está a menos de r del centro? El área πr² dividida por el área total πR², o sea (r/R)². Esa es la acumulada del radio. Igualando a u y despejando sale r = R·√u.

Box-Muller: la normal exacta

Ahora sí, la receta exacta para la normal. Box-Muller usa el mismo esquema que acabamos de ver: un ángulo al azar y un radio sacado con la transformada inversa. La diferencia es que no busca puntos parejos en un disco, sino puntos que formen una "campana en 2D", como el tercer panel: muchos en el centro y cada vez menos hacia afuera. Para esa campana, la transformada inversa del radio da √(−2·ln u). Y lo interesante es que la coordenada x de ese punto tiene distribución normal exacta. La y también, así que salen dos normales por el precio de una.

No hace falta saber derivar la fórmula para usarla: alcanza con saber que es exacta, rápida y que es la que usan casi todas las bibliotecas.

function normal(media = 0, desvio = 1) {
  const u1 = 1 - Math.random(), u2 = Math.random();   // u1 nunca es 0, porque log(0) = −∞
  const radio  = Math.sqrt(-2 * Math.log(u1));        // transformada inversa del radio
  const angulo = 2 * Math.PI * u2;                     // ángulo uniforme
  return media + desvio * radio * Math.cos(angulo);    // la x del punto (la y sería con sin)
}

Ninguna de las tres dispersiones es "la correcta": la del medio es pareja, la normal concentra los impactos sin un borde duro, y la primera concentra también, pero por accidente. Lo importante es elegirla a propósito. El siguiente capítulo da un paso más: puntos al azar que además no se pisen.
